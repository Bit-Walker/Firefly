# ADR 0001 平台边界与使用方式

状态：已接受，仅覆盖本记录列出的方向。日期：2026-10-26。

## 背景

现有实现从单板 OTA 和双板调试验证演进而来。目标已经扩展为远程多节点嵌入式开发、调试与分析系统，需要服务人类、AI 与脚本，并容纳后续硬件型号。

## 决定

1. 节点与被操作目标分离；同一硬件可以兼具两者身份，但职责及关联显式建模。
2. 现场网关作为正式节点类型，承接适合主机执行的接口、构建、烧录或深度调试能力。
3. 第一阶段以单用户、自建服务为主，预留人类、AI 和自动化客户端的独立身份及授权范围。
4. CLI/API 作为优先开发与验收入口，UI 作为共享核心业务接口的客户端之一。
5. 架构面向未来硬件扩展，当前继续使用 ESP32-S3，不在此阶段直接开发其他型号。
6. 先进行方案讨论和文档整理，后续 UI 仅按相关变更进行针对性验证。

## 理由

执行节点可能管理自身，也可能操作外接芯片或电路；目标自身在某些调试状态下无法维持管理链路。独立网关与探针使此类路径可以表达。

机器入口使人、AI 与脚本共享能力发现、权限、资源管理和结果语义，避免将浏览器操作作为自动化必经路径。

## 影响

后续设计需要稳定对象、版本化连接、能力描述、执行与数据语义。具体实验接线归入适配配置，原型中的固定身份与角色需要有迁移路径。

当前可运行原型继续保留；此次决定本身不移动代码、不改变部署，也不宣告未实现的硬件能力。

## 未覆盖事项

尚未冻结工程目录、契约定义格式、传输编码、CLI 名称、状态枚举、资源锁粒度、权限模型细节或新硬件实现方案。这些内容见 [架构索引](../architecture/README.md)，经后续讨论再分别确定。
