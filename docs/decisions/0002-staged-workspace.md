# 0002 分批整理单仓库工程

状态：已接受。日期：2026-10-27。

## 背景

用户确认工程结构方向并授权开始整理。现有原型需要继续连接实板，同时为人类和 AI 共用的接口、客户端及更多节点类型建立可维护的边界。

## 决定

采用单仓库，按 `apps/`、`packages/`、`contracts/`、`hardware/`、`profiles/` 和 `docs/` 组织。第一批迁移控制服务和网页，建立 HTTP SDK、只读 CLI 与纯分析模块，提取当前板级接口描述。

保留 `fleet/` 兼容启动入口、现有设备 HTTP 协议、固件和私有状态位置。旧模块别名指向同一份正式实现，避免产生两组应用、资源锁或操作账本。当前只有一个控制服务和数据库，不拆微服务。

未投入开发的网关、其他芯片、工作流引擎或协议目录不建立空工程。新代码优先通过 CLI、接口和定向测试验收。

## 影响

部署包必须包含完整新目录；容器构建上下文改为仓库根目录，使用公开源文件白名单。文档明确标出当前可执行入口和讨论中的目标接口。

本批没有实现完整领域分层、通用部署配置、独立 AI 身份或统一动作协议。这些仍按架构方案讨论和逐项落地；当前 `edbg.cli.query/v0` 仅稳定兼容查询包络，不冻结未来动作语义。
