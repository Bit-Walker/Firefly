# 研发顺序与完成条件

系统目标是远程多节点嵌入式开发、调试和分析，面向人、脚本及 AI。实现遇到约束时直接修订模型，不为未发布接口保留历史兼容分支；优先功能、协议与 CLI/API 验证，UI 按实际功能随后接入。

## 当前基线

已实现节点运行信息、运行镜像 SHA-256、镜像目录、严格 OTA、持久操作、UART 控制与 RX 多读者日志、显式续租、有限 I²C。构建版本仅用于显示，执行依据是版本化协议、驱动能力、健康状态、连接、启动及镜像快照。

固定台架的 MAC、角色、引脚和全局资源仍存在于调试驱动中，这是下一项要消除的架构约束。现有 I²C 先启用 UART 再执行事务的做法也需要替换，不能继续把临时包装当作通用驱动。

## 1. 驱动、连接与资源分离

连接显式声明引脚、控制器、参数和物理总线；板级描述只定义可用资源与电气限制。节点不根据 MAC 或永久 A/B 角色选择业务逻辑。

完成条件：第三个已支持型号的节点仅通过登记和配置即可执行；两种不同接线无需改服务源码；能力和节点端校验一致；引脚重叠、物理总线共享、失联后的未知占用均不能被别名绕过。

## 2. 节点原生有限执行

将 I²C、GPIO 输入/输出/脉冲等有限动作直接下沉到节点执行器，支持启动绑定、节点本地预算、序号/防重放、终结报告及明确释放，不借用 UART 会话。只支持真实驱动提供的能力，不制造未知的部分进度。

完成条件：I²C 不启用 UART；不同物理总线可以独立执行；同一物理总线互斥；超时、NACK、响应丢失、取消和节点重启有确定证据边界；读操作也不自动重放。

## 3. 串口与长期通道

UART 支持配置引脚与常用参数、监听模式和明确 TX 授权；节点确认租约修订并拒绝过期控制。接收缓冲与独立消费者解耦，关闭时报告最终接收检查点。

完成条件：有界缓存、丢失、最终排空和租约过期可测试；两个客户端看到相同的有序字节；读取不续租、不确认删除数据；被停用的旧上下文不能重新打开。

## 4. 采集、分析与探针

把有限逻辑采集和信号发生迁入统一操作、资源与产物模型。支持原始样本、时间基准、触发条件、导出和派生 UART/I²C/SPI 解码。监听、注入、主动驱动必须明确区分，并由节点能力约束。

完成条件：无触发、截断、缓冲溢出和时钟误差不冒充完整采集；可以经 CLI 完成采集、下载、离线分析与结果关联；不将服务收件时间当作边沿时间。

## 5. 开发闭环与客户端身份

构建输入、工具链、固件、符号文件及转储使用产物身份关联。增加适配器提供的外部烧录/调试、有限多节点实验与可恢复清理。人类、AI、自动化拥有独立凭证、权限范围和审计身份。

完成条件：从配置、构建、发布到观测与分析形成可复现实验；AI 可完全通过机器接口操作；授权越界和失败恢复可验证。Pico 2W 和 Linux 网关后续通过相同公共模型接入，此阶段不提前开发其驱动。

## 验证原则

先验证协议和状态机，再做必要的实板闭环。改动驱动就验证对应硬件行为；仅改服务逻辑时使用模拟故障、独立进程与事务测试。UI 未变化时不做重复浏览器检查。原始证据集中写入当前验证文件，规划保留完成条件和未解决问题，不记录逐步工作过程。
