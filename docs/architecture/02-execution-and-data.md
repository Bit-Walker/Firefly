# 执行资源与数据架构

状态：建议基线 v0.3。更新日期：2026-10-27。

本轮操作与期限的具体候选规则见 [操作契约草案](07-operation-contract-draft.md)，仍需评审后再进入执行实现。

## 三类链路

| 链路 | 职责 | 设计要求 |
| --- | --- | --- |
| 控制链路 | 发现、配置、申请控制权、提交操作、查询结果 | 有身份、版本、期限和可追溯记录 |
| 数据链路 | 串口、日志、采样和执行事件 | 有顺序、消费者游标、背压、缺失与保留范围 |
| 产物链路 | 固件、符号、原始采集和转储 | 有稳定引用、长度、校验、来源及保存策略 |

三类链路不必使用同一种传输方式。公共动作语义与节点链路编码分离，微控制器不必承载完整的服务端描述与分析逻辑。

## 租约与资源调度

租约决定谁可以控制接口，以及控制权何时失效。调度决定具体动作何时可以占用资源。长期会话不应自动等于长期独占所有底层资源。

资源模型需要覆盖节点内的 GPIO、控制器、通道和缓冲，也需要覆盖跨接口或跨节点共享的总线、目标复位和电源。应用程序正在使用的资源同样有归属，调试不能默认为可抢占。

驱动声明实际资源集合、允许共享的条件和安全退出方式；调度器据此安排。第一阶段可先采用保守互斥，但不能把按设备加锁作为永久模型。

控制权应带版本或递增编号，节点拒绝过期控制。租约失效由节点本地时间和受支持的本地机制执行；服务端仅更新数据库不能证明物理接口已释放。

资源转交需要旧持有者释放证据或满足定义好的失效条件，具体时限、漂移余量和恢复规则待第二轮确定。

## 可靠执行

建议的执行顺序：

1. 认证调用主体，解析稳定身份、目标、连接版本与能力版本。
2. 验证参数、权限、执行预算及预期状态，生成资源计划。
3. 持久保存操作与幂等关系，再确认接受。
4. 获取必要控制权并调度资源，向节点下发有边界的执行请求。
5. 节点核对运行标识、控制权和本地资源，记录执行身份后操作。
6. 逐步保存确认、执行事件、结果及产物引用，释放或续用资源。

请求追踪编号、幂等键和操作编号各司其职。相同幂等键与相同规范请求返回原操作；相同键对应不同参数应拒绝。客户端不能用生成新键的方式自动掩盖一次未知写入。

设备持久记录、内存去重、启动批次检查可以提供不同程度的防重放，但不能笼统承诺掉电或重启后物理操作恰好执行一次。无法确认的结果应保留不确定性。

具体生命周期枚举尚未冻结。必须区分接受、等待资源、运行与结束，也必须区分成功、失败、部分完成、超时和结果未确认；后到证据可用于核对原操作，而非生成重复动作。

## 取消与异常

- 客户端等待超时不等于设备取消；应返回可继续查询的操作身份。
- 请求取消不等于设备已经停止，应记录设备确认或无法确认的状态。
- 各能力定义可中断点和安全退出。烧录、电源、复位与串口不能共用一条“恢复全部输入”的规则。
- 有副作用的操作默认不离线排队；确需离线任务时，应有明确策略、有效期与执行前条件检查。
- 重启或断联后重新核对运行身份及资源，不能直接恢复旧控制权。

## 结果与证据

结果需要说明执行到了哪一步、确定发生了什么、缺失了什么，以及依据什么判定。至少区分请求接受、节点接收、驱动完成、总线确认、外部观测与目标业务确认。

例如 UART 驱动完成发送不能证明目标执行命令；I²C ACK 不能证明目标内部业务状态改变。验证级别应随动作返回，而不是统一包装成一个成功标志。

## 数据流与分析

采集端产生有序流，不同消费者持有独立游标。网页、CLI 和 AI 不应互相消耗对方的数据。数据包含节点、运行标识、流标识、序号、时间来源、缺失信息与保留范围。

支持有界读取、时间窗口、分页、摘要和通道筛选。大型原始数据保存为产物，分析结果引用原始产物、算法版本和参数；AI 不必每次读取整份波形或全部日志。

服务器接收时间、节点单调时间与采集硬件时间分别保留。跨节点事件关联需要对时关系和误差范围，不能将网络到达顺序视为精确物理顺序。

## 多节点协作

普通任务编排、就绪屏障和有精度要求的同步操作是不同能力。控制中心负责规划和收集结果，时序敏感部分尽量在节点本地执行。

本地动作序列必须有动作集合、资源、时长和取消边界。先验证实际协作场景，不提前把任意脚本执行作为所有微控制器必须实现的能力。

## 人与 AI 的授权

接口共用，主体分开。第一阶段采用可审计的身份、作用域和执行预算，为目标、动作、数据量、持续时间及并发设边界。

允许在授权范围内自动执行普通工作，不要求机器逐次模拟人工确认。不可逆动作和主机进程执行等能力另行定义权限与策略。副作用由动作及目标协议表达，不把所有读取都假设为无副作用。
