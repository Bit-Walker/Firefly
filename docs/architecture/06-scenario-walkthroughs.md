# 三个场景的对象与执行推演

状态：评审草案 v0.3，2026-10-27。本文提出下一轮实现应满足的行为，不代表现有服务或固件已经支持。请求草案见 [操作契约](07-operation-contract-draft.md)。

## UART 长期会话

### 建立与使用

连接 `console-uart` 绑定某节点的 UART 接口、目标和接线版本。用户通过 `uart.session.open` 请求串口参数和租约时长。服务冻结绑定，检查能力与权限，取得 UART 控制器及引脚资源；节点确认实际配置后，操作返回会话、租约和 RX/TX 数据流身份。

会话固定串口配置，长期保留必需的 UART 与引脚资源。打开一个 UART 不自动启用 I²C、波形或另一 UART，也不能抢占目标应用使用的外设。租约续期是独立控制请求，不由浏览器刷新或数据订阅隐式触发。

`uart.write` 是有限操作，通过会话定位配置与控制权。文本便捷命令先显式编码为字节，再走相同接口；默认不附加换行。结果至少记录请求字节数、驱动确认数和证据级别。驱动完成不等于目标执行了命令。接收字节与发送操作在时间上相邻，也不能自动判定是该操作的应答。

### 多消费者接收

接收属于数据流查询，不定义有副作用的 `uart.read` 操作。CLI 的 UART 读取便捷命令解析为指定流的有界读取或跟随订阅。

```text
UART → 节点有限缓冲 → 服务持久接收/去重 → 有序流
                                        ├─ 网页游标
                                        ├─ CLI 游标
                                        └─ AI 游标
```

只有服务确认保存的位置参与节点缓冲确认，各消费者不会分别确认或删除节点数据。流内序号在确定的 `stream_id` 与 `boot_id` 范围内单调递增；重连不能让另一启动的数据冒用旧序号。

读取返回数据、下一游标、保留范围、是否截断及明确的丢失记录。游标过期应报 `CURSOR_EXPIRED` 并提供最早可读位置；客户端显式选择追赶位置，不能悄悄跳过。超出存储和缓冲预算可以丢弃数据，但必须留下缺失证据，不能把“未收到”描述成线路静默。

订阅不授予写权限，不续租、不重新打开端口。被授权的观察者可独立读流；唯一写控制者由租约决定。观察者退出不影响其他消费者；唯一控制者断开后也不立即释放硬件，按明确的续租与到期规则处理。

### 结束与断联

`uart.session.close` 提交关闭意图，停止接受新写入。节点确认驱动关闭或达到可验证的本地失效条件后，才将资源标为可转交。服务端会话改成 closed 不是物理释放证据。

| 情况 | 应有结果 |
| --- | --- |
| 写请求未送达节点且已过派发期限 | `expired`，没有派发证据，不自动重发 |
| 驱动可能已发送，确认丢失 | 原操作进入核对，最终可为 `unknown`；新键不能自动补发 |
| 仅部分字节有可靠完成证据 | `partial`，记录已确认与不确定范围；不将 remainder 自动重发 |
| 租约到期但节点失联 | 控制权失效，资源释放仍待核对；不能立即交给新操作者 |
| 节点重启 | 旧会话结束；建立新启动上下文，不自动恢复旧写入 |

串口重开、清缓冲、目标复位均是独立且可审计的意图，不作为连接重试的隐藏动作。

## I²C 有限事务

连接 `sensor-bus` 绑定主机接口、物理总线和目标。一个请求包含一个七位地址及有序消息列表，例如“写寄存器地址，再重复 START 读一字节，最后 STOP”。一个事务内部不插入其他请求，不跨两次调用保留总线。

通常由服务内部取得短期控制上下文，调用者无需为一次有限事务手工创建会话。已存在控制会话时可以复用其授权上下文，但仍按物理总线调度每次事务。

资源至少包含主机控制器、引脚和物理总线；同一总线的不同从地址不能绕过总线互斥。若两个节点接到同一物理总线，配置必须引用同一个总线资源。不能通过分别锁住两块板来证明不会发生总线冲突。未知外部主机和接线错误不是软件调度能够消除的风险，应体现为配置前提与运行诊断。

请求的 `messages` 定义每个消息是写入还是读取，相邻消息间重复 START，最后一个消息后 STOP。节点不支持对应组合时，在动作前拒绝；不能悄悄拆成多个带 STOP 的事务。

| 情况 | 应有结果 |
| --- | --- |
| 资源忙或驱动不支持组合 | 拒绝或按显式策略等待，无总线动作 |
| 地址 NACK | 失败并记录地址阶段，不能伪造一个全零读结果 |
| 数据阶段 NACK / 部分消息完成 | `failed` 或 `partial`，按证据记录消息与字节进度 |
| SDA/SCL 被拉低 | 有界超时，标明线路状态和释放是否确认 |
| 节点执行后、结果上报前断联 | 核对原操作；默认不重复事务 |
| 自动恢复可能发时钟或 STOP | 需能力与策略明确允许，并写入证据；不能成为隐藏重试 |

读取也可能清状态、弹出 FIFO 或改变外设状态。扫描是另一种会触发探测的动作，不能视为纯查询或在能力发现时自动执行。寄存器写入已获 ACK，不等于目标业务状态已经完成；需要验证时另定义后续读取和判断规则。

## 外部目标烧录与节点更新

### 目标烧录

`target.flash` 的连接指向被烧录目标及烧录提供者。提供者可能是未来网关上的烧录工具，也可能是支持该能力的微控制器探针；当前 ESP32 固件不因存在统一动作名称就获得烧录其他芯片的能力。

请求引用不可变镜像产物及摘要，不提供任意下载 URL 或命令行字符串。镜像元数据与已注册目标配置共同生成烧录区域和兼容性计划。目标身份、芯片系列、镜像格式、地址范围、受保护区域及必要工具版本必须在擦写前检查。

建议阶段：准备 → 识别 → 兼容性检查 → 擦除 → 写入 → 校验 → 可选启动确认。擦除本身已经有副作用。只传输完成不能判成功，必须满足请求要求的校验级别。

目标复位、电源、启动模式、编程接口及与目标共享的调试/UART 控制需要统一资源计划。已有会话冲突时拒绝或等待，不静默关闭他人的会话。需要改变目标电源或复位时，由连接和能力明确声明。

| 情况 | 应有结果 |
| --- | --- |
| 目标与计划不符 | 擦除前拒绝，保存识别证据 |
| 写入中断或提供者重启 | 保留已完成阶段与不确定区域；目标可能不可启动 |
| 校验失败 | 失败，写入完成不覆盖校验错误 |
| 校验通过但业务启动未确认 | 只声明已验证编程结果；若请求要求启动确认则尚不能宣告全成功 |
| 用户取消 | 提供者在可中断点确认停止；请求取消不等于立即停止擦写 |
| 恢复 | 新的显式恢复意图，关联原操作；不把恢复当作旧请求的自动重试 |

### 节点代理更新

`node.update` 更新执行节点自身的代理，与 `target.flash` 分开。节点更新会影响控制链路及本地会话，需要节点维护资源，并检查是否存在不能中断的目标操作。

当前原型的 OTA 属于节点代理与应用合一固件的更新路径。兼容迁移时保留其现有身份和任务语义，不能据此声称通用 `target.flash` 已实现。

成功证据应关联预期镜像、原启动和新启动。版本字符串相同或新心跳出现都不足以单独证明已运行指定镜像。新代理应报告可核对的镜像身份；回滚与无法确认保留独立原因。

## 三场景得到的边界

1. 会话用于持续上下文，操作用于有限意图，读取数据流不再制造硬件操作。
2. 控制租约、调度资源和释放证据分别建模；网络断开不自动等于任一种状态。
3. 服务接受前的拒绝、已接受操作的执行结果、客户端等待超时是三个层次。
4. 结果确认与资源确认相互独立；一个已结束的未知操作仍可能阻止资源转交。
5. 所有动作由能力声明具体语义，不要求每个节点实现所有动作或证据级别。
