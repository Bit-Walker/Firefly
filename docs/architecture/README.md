# 远程多节点嵌入式开发调试分析系统架构方案

状态：讨论基线 v0.3。更新日期：2026-10-27。

系统面向人类与 AI，提供统一的节点管理、硬件交互、构建烧录、调试、数据采集及分析能力。现有 ESP32 实现作为迁移起点，具体实验接线属于适配配置，不作为公共产品模型。

## 已确认的方向

- 系统定位为远程多节点嵌入式开发、调试与分析平台，人类和 AI 均为正式使用者。
- 节点与被操作目标分离；现场网关作为正式节点类型。
- 第一阶段以单用户、自建服务为主，预留人类与 AI 的独立身份和授权范围。
- CLI/API 是优先的开发与验收入口；UI 使用同一套业务接口。
- 已开始按单仓库结构分批迁移；暂不开发其他硬件型号。

这些边界记录在 [ADR 0001](../decisions/0001-platform-boundaries.md)，工程迁移决定记录在 [ADR 0002](../decisions/0002-staged-workspace.md)。当前可执行命令见 [CLI 参考](../reference/cli-query-v0.md)。

## 文档状态约定

- **已确认方向**：来自讨论中明确接受的系统边界。
- **建议基线**：本轮评审后的设计方向，可继续修订。
- **待定**：下一轮需要选择或具体定义的事项。
- **已实现**：必须在现有实现说明或验证记录中有对应依据，不由架构文档单独宣告。

工程组织方向已确认，第一批实际路径见开发指南。统一动作的接口版本、命令语法、状态枚举和节点链路编码尚未冻结。本目录中的 `edbg` 动作示例仍表示目标接口；已经实现的兼容查询命令以 CLI 参考为准。

## 下一轮需要收敛

三个场景已形成 v0.3 候选规则，尚未升级为已接受决策。下一轮重点：

1. 评审操作接受、幂等、未知结果修订与资源释放的边界。
2. 定义连接、目标与能力修订的最小字段，明确配置与现场事实的来源。
3. 细化 UART 会话续租、事件及数据流游标、缺失和保留策略。
4. 确定兼容代理能承诺的证据与隔离级别，安排必要的节点协议更新。
5. 按第 08 章落地配置与预检查，再实施一个硬件动作闭环。

每轮讨论更新相应章节；影响模块边界或执行语义的正式决定，另写 ADR。不会为每次文字修改新建一份完整方案。
