## 软件检查

66 项机器客户端/集成测试通过，其中本批新增 14 项；44 项旧服务回归通过。草案离线校验的 6 组测试通过，当前包含 7 种动作样例。

新增检查覆盖：

- 同键重试不再次延长；不同键的同修订并发续租只成功一次。
- 参数变化同键冲突，旧修订拒绝，不延长期限的请求拒绝。
- 期限已过、关闭中、已关闭、旧启动、离线及新配置修订不能复活旧控制。
- 续租与关闭竞争后不会恢复 active；已完成续租的原键重试也不会重开。
- 续租不重置已有写入的派发/确认期限，不消除未知结果，不重复派发。
- 活动上下文快照缺失或不匹配时，停止旧控制；无法确认释放时保留 closing。
- 会话查询纯只读，CLI 通过同一 API 提交续租；会话响应通过 Schema 校验。
- 在策略修改后模拟事务中断，租约期限、修订和操作记录共同回滚。

证据：`artifacts/lease-tests.log`、`artifacts/lease-regression-tests.log`、`artifacts/lease-draft-checks.log`。竞态、断联与快照异常为隔离软件验证，没有在实板上制造网络故障或重启。

## 实板检查

保持两板固件 3.5.0，沿现有交叉 UART 接线执行：

1. 发送端建立 18 秒受管会话，接收端建立较长会话。
2. 读取租约修订 1，显式续租到接受时刻后 60 秒，修订变为 2。
3. CLI 和 SDK 重试原键，均返回同一续租操作与期限；新键携带旧修订被拒绝。
4. 等待原期限过去，在原会话中发送 20 字节标记，对端完整接收一次。
5. 关闭两端会话，均 succeeded/released，无遗留活动上下文。

续租操作：`e6544f3fba621ea8a9c9c45a`。结果 confirmation=server_policy_only、node_revision_acknowledged=false；实测的持续活动不等于设备回传了修订确认。

证据：`artifacts/uart-leases-live-check.json`、`artifacts/uart-live-renew-request.json`。文件不含管理员凭证。
