# UART 操作账本验证

日期：2026-10-27。此为执行账本阶段记录，后续 RX 接收流见 [验证记录](2026-10-27-uart-streams.md)。范围：持久提交、绑定、幂等、单次发布、查询、事件、取消和结果核对。使用方法及兼容等级见 [接口参考](../reference/uart-operations-v0.md)。

## 软件验证

- 38 项机器客户端与集成测试通过；包含 15 项本批新增或扩展的检查。
- 44 项原服务端回归通过，新旧 UART/I²C/波形入口保持原有边界。
- 模拟同键并发、重新登录、大小写十六进制归一、连接改版、未发布到期、取消与完成竞争。
- 在独立服务进程中恢复已接受操作，并验证已经发布的写入在新进程中不再发布。
- 模拟丢失派发响应、完成确认缺失、迟到确认、节点更换启动身份，以及驱动错误后不能提供字节计数。
- 验证 CLI 等待到期或等待断网保留原操作身份；结果 Schema 校验接受态与终局态。

本机证据：`artifacts/operations-tests.log`、`artifacts/operations-regression-tests.log`。故障情形为隔离数据库和模拟节点验证，不宣称在实板上制造了断电、网络故障或服务崩溃。

## 实板验证

两板维持 3.5.0，无固件更新。沿已确认 A4→B5 的交叉 UART 接线执行：

1. 通过新操作接口打开两端受管会话，节点报告 active。
2. A 发送 20 字节随机标记，B 的 UART1 记录完整相同字节。
3. 相同请求重试及重新登录后重试，均返回原写入操作。
4. 该操作只关联一条 debug_tx 记录；B 接收内容只出现一次测试标记。
5. 通过新关闭操作结束两端会话，均获 succeeded/released，检查无遗留活动上下文。

写入操作身份为 `d9107ad195ea7e8a5bf2c498`。驱动成功与对端实际接收分别核对，不将驱动报告自动当作目标业务确认。

证据：本机 `artifacts/uart-ledger-live-check.json` 和 `artifacts/uart-ledger-live-requests.json`，不包含登录凭证。

## 数据与部署

迁移 0002 前保存公开源码包及私有数据库备份；应用迁移后，原节点、任务、固件、调试、I²C、波形与连接记录数量均不变。实板检查随后新增 5 个操作、2 个会话及 1 个发送记录。

私有备份：`fleet/.state/pre-uart-ledger.local.bak`，以及自动生成的 `migration-0002-*.local.bak`。上一批源码：`artifacts/pre-uart-ledger-source.zip`。

数据库现为迁移版本 2，上一版服务的版本守卫会拒绝直接启动。需要回退时先结束并核对现场会话、停服务、备份当前数据，再选择兼容旧账本的软件修复或整体恢复迁移前数据库。整体恢复会舍弃迁移后的操作记录；不能删除迁移版本号来绕过守卫，也不能在未核对现场副作用时重放旧意图。

当前分发包会包含新模块、接口参考、响应契约及测试，不包含私有数据库或实测请求。完整性与全新解压目录验证见本机 `artifacts/uart-ledger-package-check.json`。

没有执行 OTA、设备重启、I²C 或波形动作，也没有重复运行浏览器 UI 测试。Docker 镜像构建与公网部署仍未验证。

## 尚未覆盖

本批不是通用调度器或完整远程串口：没有新多消费者流协议、续租 API、独立主体授权、其他芯片、其他动作执行或节点掉电持久去重。

执行等级明确为 legacy_uart_once。逐操作 execution_timeout_ms 在此兼容路径中是服务确认窗口，不是节点执行预算。新节点预算、持久去重与通用 fencing 仍需后续代理协议升级后验证。
