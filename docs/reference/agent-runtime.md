# 节点运行信息

节点每次认证轮询携带 runtime，契约为 contracts/agent/runtime.schema.json。当前协议 edbg.agent/v1，与构建版本分离；更换版本号不增加能力，缺少协议或驱动能力时拒绝新动作。

| 字段 | 含义 |
| --- | --- |
| protocol | 运行信息协议版本 |
| family | 芯片家族；公共形状允许扩展，当前执行适配器只实现 ESP32-S3 |
| build | 显示与诊断用构建版本，必须与轮询 version 一致 |
| uptime_ms | 当前启动的单调运行毫秒数，不是跨节点同步时钟 |
| health | pending、valid 或 error |
| image | 从当前运行 Flash 测量的镜像身份；无法验证时为 null |
| features | 唯一的版本化驱动能力名，例如 node.update/1 |

当前固件在启动时调用 ESP-IDF 的镜像验证，取得经过验证的镜像边界，再读取该范围的 Flash 字节计算完整文件 SHA-256。范围包括应用末尾附加的镜像摘要。它与 ELF 摘要、文件末尾的内部摘要、NVS 保存的 OTA 清单不同。

镜像形状为 algorithm=sha256-file-v1、sha256、size、project。服务端镜像导入采用同样的完整文件身份，并检查分段、边界、对齐校验和、附加摘要及精确文件长度；当前只支持带附加 SHA-256 的规范未签名 ESP 应用格式。签名格式需要另行实现，不能悄悄忽略尾部。

固件在 OTA 待确认阶段报告 pending，完成 TLS 在线通信和应用自检后报告 valid。服务只向健康节点接受新动作；操作接受时冻结启动、协议、镜像和能力快照，派发前发生变化会阻止执行。

node list/show 与 capability list 的 JSON 输出包含 runtime。缺少运行报告的节点仍可被查询，但不能仅凭固件版本和布尔能力列表接受受管硬件动作。未知协议、芯片家族和驱动不由服务猜测。

当前 features 仍明确写为 uart.fixed/1、i2c.fixed/1、wave.fixed/1，表示固定台架驱动，不能据此宣称动态引脚或任意节点已支持。下一阶段按研发规划拆分原生驱动与资源配置。

这些是认证节点提供的运行证据。SHA-256 能核对字节一致性，不证明发布者身份，不是硬件信任根提供的远程证明；未启用安全启动和签名链时不作相应承诺。
